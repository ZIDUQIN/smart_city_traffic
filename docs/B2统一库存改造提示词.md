# 抢票下单模块 B2 改造提示词（统一库存 + 区段模型）

## 一、核心原则（必须全文遵守）

1. 库存**全系统只有一份数据源**：`stock` 表 + 它在 Redis 中的投影 `stock:` Hash，读链路和写链路指向同一处，禁止再出现第二套可扣减库存。
2. 库存采用**相邻区段模型**：每个相邻区段独立余量，跨区段余票取 MIN，扣票时涉及区段各减 1，支持席位复用。
3. 沿用"最终一致性 + 异步补偿 + 定时对账"，禁止 XA/2PC/TCC/Seata；禁止物理删除；补偿与消费者必须幂等可重入。
4. 主流程顺序不变：**写 DB 流水 → 扣 Redis（Lua）→ 建订单 → 扣 DB 真实库存**。
5. 所有状态流转走 CAS（`UPDATE ... WHERE status = 旧值`），禁止无条件 UPDATE；Redis 判重、多区段扣减、已扣标记必须在同一个 Lua 内原子完成。

## 二、表结构（dev 环境重建，SQL 放新文件）

```sql
DROP TABLE IF EXISTS `seat_inventory`;
DROP TABLE IF EXISTS `ticket_deduct_record`;
DROP TABLE IF EXISTS `order`;
DROP TABLE IF EXISTS `stock`;

-- ① 真实库存：按 车次+席别+相邻区段 一行
CREATE TABLE `stock` (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  train_no    VARCHAR(32) NOT NULL,
  seat_no     VARCHAR(32) NOT NULL,
  segment_no  INT         NOT NULL COMMENT '相邻区段号，从 1 开始',
  remain      INT         NOT NULL,
  update_time DATETIME    NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_train_seat_segment (train_no, seat_no, segment_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ② 订单：记录起讫站序，状态 待确认/已确认/已取消
CREATE TABLE `order` (
  id           BIGINT      NOT NULL AUTO_INCREMENT,
  order_no     VARCHAR(64) NOT NULL,
  user_id      BIGINT      NOT NULL,
  passenger_id BIGINT      NOT NULL,
  train_no     VARCHAR(32) NOT NULL,
  seat_no      VARCHAR(32) NOT NULL,
  from_seq     INT         NOT NULL,
  to_seq       INT         NOT NULL,
  status       VARCHAR(16) NOT NULL,
  create_time  DATETIME    NOT NULL,
  update_time  DATETIME    NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ③ 扣减流水：同样带起讫站序，状态机仍为原 6 值
CREATE TABLE ticket_deduct_record (
  id           BIGINT       NOT NULL AUTO_INCREMENT,
  order_no     VARCHAR(64)  NOT NULL,
  user_id      BIGINT       NOT NULL,
  passenger_id BIGINT       NOT NULL,
  train_no     VARCHAR(32)  NOT NULL,
  seat_no      VARCHAR(32)  NOT NULL,
  from_seq     INT          NOT NULL,
  to_seq       INT          NOT NULL,
  status       VARCHAR(16)  NOT NULL COMMENT '扣减中/已扣减/已建单/补偿中/已补偿/已取消',
  fail_reason  VARCHAR(255) DEFAULT NULL,
  create_time  DATETIME     NOT NULL,
  update_time  DATETIME     NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_status_update (status, update_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

演示数据：G1001 两区段 × 三席别 = 6 行，每席别两段余量均为 二等 100 / 一等 20 / 商务 5。

## 三、Redis 结构与 Lua

key 规划（`{trainNo}` 为真实 hash tag，保证同 slot）：

| key | 类型 | 内容 |
|---|---|---|
| `stock:{trainNo}:{seatNo}` | Hash | field=区段号，value=该区段余票 |
| `deducted:{trainNo}:{seatNo}` | Set | 成员 orderNo，用途不变 |
| `passenger:dedup:{trainNo}:{passengerId}` | String | 值=orderNo，乘车人判重 |

**deduct.lua**：KEYS[1]=stock Hash，KEYS[2]=deducted Set，KEYS[3]=乘车人占位；ARGV[1]=orderNo，ARGV[2..]=区段号数组。

1. EXISTS KEYS[3] = 1 → 返回 -3
2. 对每个区段 HGET：nil → -2；`<=0` → -1（先全部检查，一条数据都不改）
3. 全通过：每个区段 HINCRBY -1，再 SADD orderNo，再 SET KEYS[3]=orderNo
4. 成功返回扣减后所有区段中的最小余票

**rollback.lua**：同 key 与区段数组。SREM orderNo：返回 0 直接退出返回 0（不动任何 field）；返回 1 才对每个区段 HINCRBY +1，并在 GET KEYS[3]==orderNo 时 DEL，返回 1。

注意：区段号必须作为**独立的 ARGV 逐个传入**（如 ARGV[2]="1"、ARGV[3]="2"），禁止拼成一个逗号字符串；Lua 内用 `for i = 2, #ARGV` 遍历。

**Redis 旧数据清理（必须执行，否则报 WRONGTYPE）**：现有 `stock:{trainNo}:{seatNo}` 是 String 类型，改造后同名 key 是 Hash，类型冲突无法直接写入。预热前必须先删除旧 stock key（预热方法内先 DEL 再写 Hash），并建议同时清理旧的 deducted、passenger:dedup key，保证从干净状态开始。

## 四、主流程（四步骨架与失败分支原样保留）

DTO 同步调整：`OrderRequest` 字段为 passengerId、trainNo、seatNo、fromSeq、toSeq；`OrderResponse` 保留 orderNo、status、message 等字段。

- 步骤0：雪花 orderNo，按 `fromSeq..toSeq-1` 算区段数组
- 步骤1：INSERT 流水（扣减中，含 from/to）；失败直接 ROLLBACK，无补偿
- 步骤2：deduct.lua；-1/-2/-3/异常均 CAS 扣减中→已取消，ROLLBACK，**不回补**；成功 CAS 扣减中→已扣减
- 步骤3：INSERT 订单（待确认，含 from/to）；失败：rollback.lua + CAS 已扣减→已补偿，**禁止 cancelOrder**（订单不存在）
- 步骤4：StockService 新增方法（实现类加 `@Transactional`）按区段逐条 `UPDATE stock SET remain=remain-1 WHERE train_no=? AND seat_no=? AND segment_no=? AND remain>0`，循环内任一条失败整体回滚：
  - 失败：cancelOrder + rollback.lua + CAS 已扣减→已取消
  - 成功：订单 待确认→已确认，再 CAS 已扣减→已建单；CAS=0（被对账接管）→ cancelOrder + rollback + 抛 BizException("本单已超时被补偿任务接管，请重新下单")，禁止 COMMIT；CAS=1 返回 COMMIT
- 补偿动作自身失败：log.error + alarm，保持原状态，交定时任务。

## 五、读链路改造（三级缓存框架保留，只换数据源）

1. 删除 `seat_inventory` 表、SeatInventory 实体/Mapper/XML 及旧 `/api/ticket/preheat` 入口；预热合并到 `/api/orders/preheat`，新契约为 `POST /api/orders/preheat?trainNo=xxx`（可选 `seatNo`，**不再接收 remain 参数**）：从 stock 表读取该车次全部"席别 × 区段"行，先 DEL 旧 key 再写入对应 stock Hash。
2. 余票接口改为 `GET /api/ticket/remain?trainNo=&seatNo=&fromSeq=&toSeq`，链路不变：Caffeine 本地（1 秒）→ Redis stock Hash → DB stock 表，响应保留 `source`；余票 = 涉及区段 MIN，单区段直接取该值。`RemainResponse` 字段同步改名：`trainId`→`trainNo`（String）、`seatType`→`seatNo`。
3. 缓存空值防穿透保留，空值 key 随接口口径改为 `null:train:{trainNo}`，TTL 沿用现值；删除旧 `ticket:` key，代码中不得残留引用。
4. 同步更新 `api-test.http`：余票查询、预热、下单用例全部改为新参数与新接口。

## 六、MQ 与对账（口径不变）

- 事务消息生产者/监听器不变；回查：已建单→COMMIT，已补偿/已取消→ROLLBACK，扣减中/已扣减/补偿中→UNKNOWN。
- DownstreamConsumer 按 orderNo SETNX 幂等，重试超 3 次告警并 ACK。
- 对账任务：cron、分布式锁、只扫扣减中/已扣减且超 5 分钟、先 CAS 补偿中；矩阵不变，回补区段数组从流水 from/to 计算；已确认订单只补流水、禁止动库存；单条异常不中断。

## 七、自检清单（完成后逐条列出）

1. 读写是否同源（同一 stock 表 + 同一 stock Hash，无第二套库存）
2. 主流程顺序是否为 写流水→扣Redis→建单→扣DB库存
3. 每个失败点是否独立分支、无通用 catch
4. 步骤2失败是否未回补
5. 步骤3失败是否未调 cancelOrder
6. 步骤4失败是否调了 cancelOrder
7. 判重是否走 passenger:dedup（而非订单号/deducted 集合）
8. 多区段扣减是否先全检查再全扣、不存在扣一半
9. 余票是否按区段取 MIN
10. 结尾 CAS 已建单失败是否主动回滚
11. 回补是否全走 rollback.lua、区段数组与扣减一致、SREM 幂等
12. 已确认订单是否只补流水不动库存
13. 回查中间态是否返回 UNKNOWN
14. 下游消费是否按 orderNo 幂等
15. seat_inventory、ticket: key 及旧 stock String key 是否清理完毕，代码中无残留引用，api-test.http 已同步更新
