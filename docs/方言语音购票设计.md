## 1. 背景与目标

### 1.1 要解决的问题

铁路购票已高度线上化，但有一群被结构性排除的用户：**只会说方言、不会说普通话的老年人**。

- 打字不会，拼音不会，输入法用不来；
- 普通话说不好，对着手机说普通话，识别结果驴唇不对马嘴；
- 界面字小、按钮小、流程长，看不清也记不住。

行业现状（用于界定"我们不是首创，但要做得完整"）：

| 已有实践 | 做了什么 | 没做什么 |
|---|---|---|
| 12306 敬老版（2021） | 大字、简化登录、读屏 | 语音是"读屏播报"，**听不懂方言** |
| 12306 语音购票（2022 论文） | 融合铁路领域知识提升专名识别 | **仅普通话** |
| 12306 老年电话订票（2026） | 60 岁以上人工客服代订 | 靠人兜底，**不是机器能力** |
| 电信山东方言大模型 | 覆盖 16 市方言，准确率 >90% | 客服场景，**不是购票** |
| 印度多语言售票机（论文） | 英语/印地语/卡纳达语等 | **非中文方言**，非可运行工程 |

**结论：方言 + 铁路购票 + 老年交互三者合一的完整实现，目前没有可用项目。**

### 1.2 目标

让不会说普通话的老人，**用家乡话把票买对**。

1. **听得懂**：方言语音能转成文字（自动判别 + 手动指定兜底）；
2. **买得对**：站名、日期、席别、人数经纠错与确认，不买错票；
3. **用得下**：老人独立完成一次订票，不需要旁人指导。

### 1.3 非目标

| 不做 | 原因 |
|---|---|
| 让 AI 直接下单/支付 | 既定原则：模型只读，写操作必须人点 |
| 服务端保存对话与音频 | 语音含个人信息；服务器存储成本与合规风险不可接受 |
| 支持全部 202 种方言 | MVP 聚焦可测方言，架构留扩展位 |
| 离线端侧模型 | 设备算力与包体不可控，远期 |
| 多轮指代（"那个便宜的"） | 先做"第几趟"这类简单指代，复杂指代留后 |
| 替代现有订票页面 | 语音是**入口**，下单仍走现有确认订单与收银台 |

### 1.4 价值主张（简历与答辩的准确表述）

> 面向不会说普通话的老年群体，实现"方言语音 → 铁路实体纠错 → 确认 → 下单"的完整闭环；核心不在语音识别（采购第三方能力），而在**方言场景下的铁路专有名词纠错**与**防误购的确认设计**。

不得表述为"首创方言购票""自研方言识别模型"。

## 2. 需求

### 2.1 用户画像

| 画像 | 特征 | 关键约束 |
|---|---|---|
| 张大爷（68，陕西关中） | 只会关中话，手机只会打电话、看微信 | 说话慢、停顿长；不认识"二等座"等术语 |
| 李阿姨（62，四川） | 川普混说，能看懂大字 | 对"确认""取消"分不清，怕点错 |

### 2.2 核心场景

**场景 A：全语音订票（P0）**

```
老人按住话筒说："我明儿个想去北京，两张，最便宜的那种"
→ 方言 ASR → 站名纠错（多候选时让用户点）→ 意图解析
→ 查票 → 大字卡片 + 语音播报 → 点"对，就这个" → 确认订单 → 支付
```

**场景 B：识别不准时的纠偏（P0）**

```
识别结果："从西岸到北金西"
→ 纠错打分：西安北 0.94 / 西安东 0.94 / 咸阳北 0.76
→ 大字卡片："您是要从 西安北 出发吗？" 候选可点
→ 老人点"西安北" → 继续
```

**场景 C：无可用方言 ASR 时降级（P0）**

```
未配 key / 识别失败 / 无网络
→ 提示"没听清，您可以直接点下面的话说"
→ 提供 6 个常用句式按钮："我要去北京""明天走""两张票""最便宜的"
→ 点击即等价于说了一句话，继续走后续链路
```

### 2.3 功能清单

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 按住说话录音 | 手动控制起止，避免 VAD 切碎 |
| P0 | 方言自动判别 + 手动指定 | 默认 auto，失败可切 |
| P0 | 站名纠错与候选重排 | 拼音相似度 + 业务反查，Top5 候选 |
| P0 | 确认链 | 文本回显 / 语音复述 / 点击确认 |
| P0 | 意图解析（站/日期/席别/人数/出发时段） | 规则优先，模型兜底 |
| P0 | 查票与卡片选择 | 复用 `TicketService.search` |
| P0 | 大字模式 | 字号 ≥ 20px，按钮 ≥ 48px |
| P1 | 语音播报（TTS） | 浏览器 SpeechSynthesis |
| P1 | 常用句式快捷按钮 | 无 ASR 时的降级入口 |
| P1 | 语料回归评测 | `tools/voice-eval.ps1` + 30 条语料 |
| P2 | 多轮修正（"不是北京，是上海"） | 依赖会话状态 |
| P2 | 方言 TTS 音色 | 浏览器中文音色即可，方言音色暂无 |
| P3 | 端侧离线识别 | 远期 |

### 2.4 非功能需求

| 维度 | 指标 |
|---|---|
| 单次识别延迟 | ≤ 3s（≤30s 音频） |
| 端到端（说话→出候选） | ≤ 6s |
| 音频大小 | ≤ 2MB / ≤ 30s |
| 音频留存 | **0**，内存处理，不落盘 |
| 隐私 | 录音前显式授权提示；音频不入库、不入日志 |
| 可用性 | 无 ASR 供应商时仍可完成订票（打字/句式按钮） |

## 3. 总体设计

### 3.1 架构

```
┌────────────────────── 浏览器（老人端） ──────────────────────┐
│ [按住说话] ─ AudioWorklet 采 16kHz 单声道 PCM ─ WAV（44B 头） │
│      │                                                      │
│      └─► POST /api/voice/recognize (multipart)               │
│                        │                                    │
│  大字面板 ◄── {text} ───┘                                    │
│      └─► POST /api/voice/interpret {text}                   │
│                        │                                    │
│  站名候选/班次 ◄── {candidates, intent, trains} ──┘          │
│      └─► 点选车次 → 复用现有「确认订单」→ 收银台（人点支付）   │
└──────────────────────────────────────────────────────────────┘
                             │
┌────────────────── 服务端（Spring Boot） ──────────────────────┐
│ VoiceController                                              │
│   ├─ AsrService（接口）                                      │
│   │    ├─ XfyunAsrService（讯飞听写大模型 V2.0，真实现）      │
│   │    ├─ AliyunAsrAdapter（备选，未实现）                    │
│   │    └─ MockAsrAdapter（无 key 时原样返回 debugText）      │
│   ├─ StationCorrector（站名纠错：内存索引 + 拼音打分 + 反查） │
│   ├─ IntentParser（规则优先，模型兜底＝未接入）               │
│   └─ TicketService.search()（既有，只读）                     │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 前端状态机

```
[IDLE] ─按住─► [RECORDING] ─松开─► [UPLOADING]
                                       │成功            │失败
                                       ▼                ▼
                              [CORRECTING]        [FALLBACK]
                                       │确认            │句式/打字
                                       ▼                │
                              [INTERPRETING] ◄──────────┘
                                       ▼
                              [CHOOSING] ─点卡片─► [ORDER] ─► [PAY]
                                       │无结果
                                       ▼
                                  [EMPTY] → 提示改期/换站
```

约束：任意状态可"重说一次"回 RECORDING；除 ORDER/PAY 外均可取消。

> 引入"问出发时间 → 推荐一趟"之后的完整状态机见 `docs/老人购票流程设计方案.md` 第 9 节。

### 3.3 关键设计决策

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | 方言自动判别优先，手动兜底 | 老人说不清自己是什么方言，实际多为"方言味普通话" | 判别错误时需手动纠正入口 |
| D2 | 按住说话，不用 VAD | 老人语速慢、停顿长，VAD 会切碎 | 用户需按住 → 按钮做大、支持 30s |
| D3 | 站名纠错放在 ASR 之后、模型之前 | 模型对"西岸"无从判断；封闭词表可精确重排 | 需拼音索引（新增 pinyin4j） |
| D4 | 意图解析规则优先 | "明天""两张""最便宜的"规则可全命中，省延迟省成本 | 规则需维护；覆盖不到才调模型 |
| D5 | AI 只读，下单支付必须人点 | 误购责任边界 | 多一步点击（本就必要） |
| D6 | 音频不落盘、会话不落库 | 隐私与成本 | 不支持跨设备续聊（不需要） |
| D7 | ASR 做成适配器 | 不绑供应商；无 key 也能演示 | 多一层抽象 |
| D8 | 前端编码 WAV 16k 单声道 | 后端零转码依赖（不引 ffmpeg） | 前端 AudioWorklet 约 60 行 |
| D9 | **不引入 RAG**，用工具直查结构化数据 | 数据是结构化的且要求精确（余票、票价）；RAG 会把精确查询降级为模糊检索 | 失去非结构化文档问答（本模块不需要） |

### 3.4 为什么不用 RAG

| 维度 | 本模块实情 | 结论 |
|---|---|---|
| 数据形态 | 车站/车次/余票/票价全部结构化（MySQL + Redis） | SQL 可精确取值，不需语义检索 |
| 结果要求 | 必须给出精确数字（450.00 元、余 50 张） | 向量检索给不出数字 |
| 数据规模 | 61 站、100 车次 | 不需要 embedding + 向量库，属过度设计 |
| 纠错目标 | 站名的**读音**相似（"西岸"↔"西安"） | 向量相似度会把西安/咸阳/渭南判为相似，方向错误；应用拼音 + 编辑距离 |
| 模型职责 | 把口语翻译成结构化字段 | 属工具调用场景，不是知识检索 |

**唯一合理的 RAG 场景（P2，独立旁路）**：铁路规章问答（儿童票、行李、退改签）。做成独立"客服问答"入口，与订票主链路解耦，不参与下单。

## 4. 接口设计

### 4.1 通用约定

- 鉴权：`Authorization: Bearer <token>`；语音同样要求登录。
- 返回：沿用 `Result<T>` `{code, message, data}`。

| code | 含义 | 前端处理 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数错误 / 人数超限 | 提示"再说一次"或业务文案 |
| 401 | 未登录/过期 | 跳登录 |
| 500 | ASR 供应商异常 | 进兜底（句式/打字） |
| 2001 | 未识别出有效车站 | 进兜底 |
| 2002 | 该日期无可用车次 | 提示换日期/换站 |

> 注：`BizException` 经 `GlobalExceptionHandler` 返回 **HTTP 200 + body 内 code=400**，前端按 body 判。

### 4.2 识别接口

`POST /api/voice/recognize`（multipart/form-data）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| audio | file | 是 | WAV 16kHz 单声道 16bit，1–30s，≤2MB（mock 时可省） |
| dialect | string | 否 | `auto`（默认）/`sichuan`/`shaanxi`/… |
| sessionId | string | 否 | 前端 UUID，仅日志串联，不落库 |
| debugText | string | 否 | 仅 mock 生效：原样作为识别结果，用于无 key 跑通 |

响应 `data`：`{rawText, dialect, provider, confidence, elapsedMs}`。

- `rawText` 是 ASR 原样输出，**不做纠正**——纠错是下一步的事，识别层不背这个锅；
- `confidence` 仅用于提示，不参与业务判定（判定看纠错分档）；
- `provider`：`xfyun`/`aliyun`/`mock`，便于排障。

**职责边界**：本接口只做"音频 → 文字"。浏览器自带识别、打字输入等入口可跳过本接口，复用后续链路。

### 4.3 意图解析接口

`POST /api/voice/interpret`

请求：

```json
{"text":"我从西岸到北金西 明儿个 两张","fromStation":null,"toStation":null,
 "lastUsedFrom":"西安北","todayHint":"2026-11-17"}
```

`fromStation`/`toStation` 由前端在用户点选候选后回填；null 表示交给后端纠错。

响应 `data`：

```json
{"correctedText":"从西安北到北京西 明天 两张",
 "stationCandidates":{"from":[{"stationName":"西安北","city":"西安","score":0.94,"matchedText":"西安北"}],
                      "to":[{"stationName":"北京西","city":"北京","score":0.94,"matchedText":"北金西"}]},
 "intent":{"fromStation":"西安北","toStation":"北京西","travelDate":"2026-11-18",
           "seatPreference":"SECOND_CLASS","passengerCount":2,"parserSource":"rule"},
 "needStationConfirm":false,"missingStations":[],"trains":[],
 "speech":"明天，西安北到北京西，二等座两张，对吗？","emptyReason":null}
```

关键约束：

- `needStationConfirm=true` 时 `trains` 必须为空——站名没定就不查票、不出卡片；
- `missingStations` 指出缺哪个方向，前端据此高亮候选区；
- 站名确认后再次调用（带 fromStation/toStation），返回 `needStationConfirm=false` 与车次列表；
- `speech` 由后端按模板拼装（不调 TTS，交前端朗读），保证播报口径与卡片一致，避免念错价格；
- **票价为 null 的席别**：保留但 `price=null`，前端置灰不可选，`speech` 念"票价待定"，绝不念"null 元"。

### 4.4 调用约束

两个接口**都是只读**，不写任何表；`recognize` 不做业务查询，`interpret` 只调 `TicketService.search`（读）。不提供"语音直接下单"接口。

## 5. 站名纠错设计（核心）

### 5.1 问题建模

输入：ASR 出来的文本（含站名片段）。输出：两个方向上的候选站 + 分数 + 命中了哪几个字。

难点：方言下地名发音与普通话差异大，且 ASR 会输出同音字（"西岸"/"西安"、"北金"/"北京"）。

### 5.2 词表与索引

数据源 `station` 表（61 条）。表里没有拼音字段，项目也没有拼音依赖 → 引入 `pinyin4j`，启动时构建内存索引（61 条，微秒级）：站名、全拼、首字母、city 拼音。

多音字风险：61 个站名基本不含多音字；若有，以"铁路通用读法"写死覆盖表（预计 ≤5 条）。

**前置防线：热词注入（最划算的一招）**

纠错是"事后补救"，更好的是让 ASR 一开始就少错。讯飞听写支持 `context.bias.hotword`：

- 把 61 个站名、常见车次前缀、"二等座/一等座/商务座"作为热词上传；
- 解码时优先输出这些词，专名错误率显著下降；
- 成本接近 0，只在词表变更时同步一次。

顺序：**热词先降错误率 → 纠错兜剩下的 → 人确认拍板**，三层缺一不可。

### 5.3 打分算法（按实现回写）

对每个候选站 S 与片段 T 的所有长度 2–5 子窗口 `win` 比对，取最高分：

```
v = 0.50 * charSim      逐字音节相似（同音算满分）
  + 0.22 * pinyinSim    全拼编辑距离相似
  + 0.13 * initialSim   首字母串相似
  + 0.05 * lenMatch     长度相等给 1.0
  + 0.10 * coverage     窗口字数 / 站名长度

win 与窗口完全相同        → +0.20
片段的城市名命中该站 city → +0.08
模糊路径最终封顶          → FUZZY_CAP = 0.94
窗口覆盖率 < 0.60         → 该窗口不参与打分
```

**三个必须记住的常量**

| 常量 | 值 | 作用 |
|---|---|---|
| `FUZZY_CAP` | 0.94 | 模糊分永远低于精确命中的 1.0，为"整词命中"留出差距 |
| `MIN_WINDOW_COVERAGE` | 0.60 | 挡"半截字当整站名"：`上海`(2) 对 `上海虹桥`(4) 覆盖率 0.5 被掐掉；`西安`(2) 对 `西安北`(3) 是 0.67，保留 |
| 精确短路 | — | 片段**包含完整站名**（如"西安北"在"从西安北到北京西"里）直接给 1.0 并跳过模糊打分 |

**排序**：分数降序 → 实际匹配字数降序 → 站名长度降序。

前两条缺一不可：`上海红桥` 场景里 `上海虹桥`（匹配 4 字）与 `上海松江`（只匹配"上海"2 字）曾并列，靠"匹配字数"才分出先后。

### 5.4 判定分档

| 常量 | 值 | 含义 |
|---|---|---|
| `MIN_CANDIDATE` | 0.40 | 低于此分不进候选，直接当"没听出来" |
| `AUTO_SCORE` | 0.85 | 自动采用门槛 |
| `AUTO_GAP` | 0.05 | 与次高分差距低于此值算"分不开"，交给用户点 |
| `MAX_CANDIDATES` | 5 | 每方向最多保留候选数 |
| `PROBE_LIMIT` | 3 | 每方向参与反查的候选数，最多 3×3 = 9 次 |

同方向两个候选都在 0.85 以上且差 < 0.05（如"北京"可指北京西/北京南），**强制点选**，不允许自动选。

### 5.5 方向切分

`extractStationSegment` 规则（按优先级）：

1. "从/自/由 A 到/去/往 B" → A=from，B=to；
2. "去/到/往 B"（无出发词）→ B=to，**from 标记缺失**；
3. "A 到 B"（无虚词）→ 按出现顺序 A=from、B=to；
4. 仅出现一个地名且无方位词 → 判为 to（"我要去北京"是最高频表达）；
5. 两个以上地名无法判定 → 全部作候选，强制点选。

方言口语干扰词（先剔再匹配）：`我要 / 俺要 / 我想 / 走一趟 / 回 / 去一趟 / 明儿个 / 后儿个 / 多少钱 / 最便宜 / 麻烦`。

### 5.6 出发站缺失的兜底

老人最常见说法是"我要去北京"，根本不提从哪走。按顺序兜底：

1. `lastUsedFrom`（前端 localStorage 上次使用）→ 预填并语音确认"还是从西安北走吗？"，用户点"是"才采用；
2. 城市级匹配：与上次订单出发城市一致 → 预填同城主要站并确认；
3. 都没有 → 必须让用户从"常用站"点选（默认展示同城/同省车站，最多 8 个）。

**禁止静默使用某个默认出发站。** 老人被默认带去错城市的票，是本模块最不可接受的错误，宁可多问一句。

### 5.7 用真实车次反查校验（业务层最后一道算法）

纯文本相似只能判断"听起来像"，判断不了"这条线到底通不通车"。做法：

1. from 候选 × to 候选（最多 3×3 = 9 组）逐组查"这条线有没有车"；
2. 只有一组通车 → 直接采用（哪怕文本分只有 0.7，业务上唯一成立）；
3. 多组通车 → 仍让用户点选，卡片上标注"这条线有 N 趟车"；
4. 全部不通车 → 不删候选，退化为纯文本判断（可能只是当天没车，不代表站名错）。

示例：`西岸 → 北金西` 的 from 候选 `{西安北 0.94, 西安东 0.94}`、to 候选 `{北京西 0.94}`：
西安北→北京西 有 6 趟，西安东→北京西 无车 → 直接落到"西安北→北京西"，不打扰用户。

**价值**：把"文本相似"升级为"业务可成立"。**代价**：每组一次查询（走 Redis/MySQL，<100ms）。**优化项**：反查只需知道"通不通车"，不该走完整查票（后者会连带算每趟车 × 3 席别的余票与票价），应改为是否存在判定，详见 `老人购票流程设计方案.md` 第 11 节第 5 项。

## 6. 方言 ASR 接入

### 6.1 抽象

```java
interface AsrService {
    AsrResult recognize(byte[] wav, String dialect); // text/confidence/provider
}
```

| provider | 适用 | 说明 |
|---|---|---|
| `xfyun` | 生产 | 讯飞语音听写大模型 V2.0，WebSocket + URL 鉴权（HMAC-SHA256） |
| `aliyun` | 备选 | Fun-ASR，仅留适配器接口，未实现 |
| `mock` | 开发/无 key | 把 `debugText` 原样返回，跑通整条链路 |
| `browser` | 降级 | 前端 Web Speech 识别，后端只收文本（跳过 recognize） |

### 6.2 方言参数映射

前端只传语义化的 `dialect`，由适配器转供应商参数，避免前端绑死供应商：

| 语义值 | 含义 | 讯飞 accent |
|---|---|---|
| auto | 自动判别 | `mandarin`（+ 语言自适应） |
| sichuan | 四川话 | `sichuanese` |
| shaanxi | 陕西话（关中） | `mandarin`（方言加强） |
| yue | 粤语 | `cantonese` |
| northeast | 东北话 | `mandarin`（方言加强） |

讯飞对"陕西话"没有独立 accent 值，只能靠"普通话模型 + 领域词表纠错"弥补——这再次说明**纠错层是本模块的核心，不是点缀**。

### 6.3 配置

```yaml
voice:
  asr:
    provider: mock          # mock | xfyun | aliyun
    max-duration-seconds: 30
    max-bytes: 2097152
  xfyun:
    app-id: ${XFYUN_APP_ID:}
    api-key: ${XFYUN_API_KEY:}
    api-secret: ${XFYUN_API_SECRET:}
    hotwords: true
  dialect:
    default: auto
    supported: [auto, sichuan, shaanxi, yue, northeast]
  rate-limit:
    per-user-per-minute: 6
```

**安全要求**：key 一律走环境变量；本地真值放 `application-local.yml`（已 gitignore），主配置只留空占位 + `spring.config.import: optional:classpath:application-local.yml`。

### 6.4 音频规范（前后端契约）

| 项 | 规范 |
|---|---|
| 容器 | WAV（PCM + 44 字节头） |
| 采样率 | 16000 Hz |
| 声道 | 1 |
| 位深 | 16 bit |
| 时长 | 1–30s（<1s 提示"太短，说长一点"） |
| 大小 | ≤ 2MB |
| 前端实现 | `getUserMedia` + `AudioContext({sampleRate:16000})` + `AudioWorklet` 收 Float32 → Int16 → 拼 WAV 头 |
| 上传 | `FormData`，字段名 `audio` |

**浏览器硬约束**：`getUserMedia` 只在安全上下文可用（`https://` 或 `http://localhost`）。局域网 `http://192.168.x.x` **无法录音**，必须配 HTTPS。演示前要说明，别到现场才发现话筒点不动。

## 7. 意图解析

### 7.1 抽取字段

| 字段 | 取值 | 示例 |
|---|---|---|
| fromStation | 站名 | 西安北 |
| toStation | 站名 | 北京西 |
| travelDate | LocalDate | 2026-11-18 |
| seatPreference | SECOND_CLASS / FIRST_CLASS / BUSINESS | SECOND_CLASS |
| passengerCount | 1–5 | 2 |
| departTimePreference | 时段/时刻（M5 新增） | 上午 |

> **座席编码以库里真实值为准**：`stock_capacity.seat_no` 实测取值为 `BUSINESS` / `FIRST_CLASS` / `SECOND_CLASS`（**不是** `BUSINESS_CLASS`）。文档与语料的期望值必须对齐这三个值。

### 7.2 规则优先（`parserSource=rule`）

1. **日期**：今天/明天/后天/大后天/这周六/周日/11月20号/下周X。相对日期基于 `LocalDate.now()`，超出 7 天窗口提示"只能买 7 天内的票"；
2. **人数**：`N张`/`N个`/`N位`/`两个人`/`一张`；未提默认 1；>5 抛 `BizException("一次最多买 5 张票")`；
3. **席别**：`最便宜/便宜的`→二等；`一等`→一等；`商务/头等`→商务；未提默认二等；
4. **方位**：`从/自/由 X`→from；`到/去/往/回 X`→to；`X 到 Y` 双站。

**默认值**：未提日期 → 当天，**不自动跳到明天**——自动跳会让老人以为买的是今天。

### 7.3 模型兜底（`parserSource=model`，未接入）

规则缺字段时调用（Spring AI + DeepSeek），约束：

- 结构化输出（JSON Schema：上面字段 + `needStationConfirm`）；
- 提示词注入当前日期、7 天窗口、61 站清单、席别枚举；
- **模型不得输出订单号、金额、乘客 ID**；金额一律后端查库计算；
- 输出必须过校验：站名在 61 条内、日期在窗口内、人数 1–5，否则丢弃按规则默认。

> 当前状态：`parserSource` 恒为 `rule`，M2 未开工。已做过 30 条语料回归（96.7%→100%，见提示词文档第 17 章），先看规则失败率再决定 M2 要不要做。

### 7.4 只读约束（硬性）

```
允许：读车站列表、读日期、读文本意图
禁止：创建订单、支付、退款、改库存、写任何表
实现：AiService 不注入任何 Mapper/Service 的写方法；仅注入 TicketService（读）
```

`/api/voice/*` 全链路无 `insert/update/delete`。

### 7.5 张数 ≠ 乘车人

语音只能确定"要几张"，确定不了"是谁"：

- `passengerCount` 只用于 ① 语音播报 ② 确认订单弹窗的预选提示；
- 进入弹窗后仍由用户**手动勾选** N 位；
- 勾选数 ≠ `passengerCount` 时提示"您说的是两张，现在选了 1 位"，**不阻止**用户改主意；
- 语音链路全程不接触 `passengerId`，不替用户选人。

## 8. 前端交互设计

### 8.1 入口与界面

- 位置：订票页搜索区右上，按钮"**说方言订票**"（大字 + 话筒）；
- 面板：全屏遮罩弹层，白底，字号基准 20px（比常规 14px 放大 43%）；
- 结构：① 顶部方言标签 ② 中部大字文本区 ③ 站名候选卡片（高 ≥ 56px）④ 底部按住说话大按钮（直径 ≥ 96px）⑤ 兜底 6 个句式按钮。

### 8.2 录音交互

| 动作 | 行为 |
|---|---|
| 按下 | 请求麦克风权限；开始采集；按钮变红、显示计时 |
| 按住 | 实时秒数；>25s 提示"快说完了"；30s 自动停止提交 |
| 松开 | 停止采集，编码 WAV，POST 识别 |
| 上滑取消 | 滑出按钮区域松手 → 取消，不提交 |

触屏与鼠标均支持（`pointerdown`/`pointerup`/`pointercancel`）。

### 8.3 确认链（防误购）

| 层 | 内容 | 强制 |
|---|---|---|
| 1. 文本回显 | 大字"您说的是：我从**西安北**到**北京西**，明天，两张" | 是 |
| 2. 语音复述 | "11月18号，西安北到北京西，二等座两张，对吗？" | 默认开，可关 |
| 3. 点击确认 | 必须点"**对，就是这个**"；点"不对，重说"回录音 | 是 |

**关键约束**：`needStationConfirm=true` 时禁止展示车次卡片，必须先选站。

### 8.4 播报模板（后端拼装，前端朗读）

```
单条："{月}月{日}号，从{出发}到{到达}，{N}趟车，最便宜{价格}元，{余票描述}"
多条："{月}月{日}号，从{出发}到{到达}，一共{N}趟车，最早{dep}出发，最便宜{价格}元"
无票："{月}月{日}号，从{出发}到{到达}没有余票，要不要换个日期？"
余票描述：remain>5 "余票充足" / 1–5 "只剩{N}张" / 0 "没票了"
价格：price=null → 念"票价待定"，绝不念数字
```

### 8.5 错误提示（口语化）

| 情况 | 文案 |
|---|---|
| 没听清 | "没听清，您再说一遍，或者点下面的话" |
| 站名不确定 | "您说的是从哪儿走？点一个" |
| 日期超窗 | "只能买 7 天以内的票" |
| 无车次 | "这天没有车，换个日子试试？" |
| 识别服务异常 | "识别服务歇会儿，您先打字或点下面的句子" |

**车次不给 36 条清单、不给三席别并排**，改为"一行一趟 + 问一句出发时间 + 推荐一趟"。完整规则（列表形态、时段词表、推荐优先级、播报文案、确认后的余票重校验、乘车人）见独立文档：

## 10. 安全与隐私

1. **录音前显式提示**："点开始后会录下您说的话，只用来识别车票，不会存下来"；
2. 音频仅内存流转，`max-bytes` 校验；
3. 日志脱敏：只记 `sessionId`、时长、字节数、耗时、结果长度，**不记文本内容**；
4. Key 全走环境变量，禁入 git；
5. 限流：单用户 6 次/分钟（内存滑动窗口）；
6. **误购责任边界**：AI 只输出建议，订单由用户点击确认；
7. 不记录声纹，不做说话人识别。

**限流已知局限**：计数在各自 JVM 内存，多实例部署时每实例独立计数，实际额度变成"N 倍"。要精准需换 Redis `INCR + EXPIRE`，不列入本期。

## 11. 性能与成本

### 11.1 延迟（实测，2026-11-17）

| 项 | 实测 |
|---|---|
| 5.11s 音频 | **2.2~2.5s**（三次一致） |
| 18.01s 长句 | 7.07s |
| 站名纠错（61 条 × 子串） | < 20ms |
| 规则解析 | < 10ms |
| 查票（含 Redis） | < 100ms |

关键优化：音频是**松手后整段发**，不必按官方建议 40ms/帧实时节奏，压到 **10ms/帧**后从 7.3s 降到 2.2s。不是流式场景，用流式的节奏只会白等。

### 11.2 计费

- 一次一句话识别 ≈ 1 次调用；
- 不做流式（流式按秒计费且更贵）；限制 30s；短句优先；
- 额度：2 万次 / 并发 50 / 到期 2027-02-15。

### 11.3 并发与限流

| 项 | 策略 |
|---|---|
| 单用户 | 6 次/分钟（内存滑动窗口） |
| 全局 | ASR 并发 ≤ 10（线程池隔离） |
| 超时 | ASR 5s 超时，超时即降级 |
| 失败重试 | 不自动重试（避免重复计费），提示用户重说 |
| 评测 | 跑批需临时放宽 `per-user-per-minute`（系统属性覆盖 yml），否则 1 分钟内连打 30 条会被限流拦成 3/30 |

## 13. 风险与对策

| 风险 | 影响 | 对策 | 兜底 |
|---|---|---|---|
| 方言 ASR 对站名识别差 | 订票失败 | 热词注入 + 封闭词表重排 + 候选点选 | 句式按钮/打字 |

| ASR 限流/欠费 | 服务不可用 | 适配器可切换 + mock | 提示稍后 |
| 不支持 AudioWorklet | 采集失败 | 检测降级到 MediaRecorder + 后端转码（P2） | 打字 |
| 长按耗电/手抖 | 体验差 | 30s 上限 + 上滑取消 | — |
| 模型胡编站名 | 买错票 | 白名单校验 + 纠错层二次校验 | 拒绝并降级 |
| 老人误点确认 | 误购 | 确认链 + 金额大字 | 退票兜底 |
| 播报停不下来 | 体验差 | `pause → cancel → resume` 三连 + 关窗即不播 | — |
| 试通车打太多库 | 高并发下拖库 | 改轻量存在性查询 + 缓存（见独立文档） | — |

## 16. 评审结论

### 16.1 2026-11-16 确认

| # | 待确认项 | 结论 |
|---|---|---|
| 1 | MVP 方言范围 | **四川话 + 关中话** |

### 16.2 2026-11-17 补充确认

| # | 议题 | 结论 |
|---|---|---|
| 6 | 是否用 RAG | **不用**。结构化数据要精确值，RAG 会把精确查询降级为模糊检索 |
| 7 | 会话存储位置 | **只在浏览器内存**，不做服务端会话 |
| 8 | 写操作授权 | **不交给模型**，模型只读，下单/支付必须人点 |
| 9 | 车次展示 | **不给 36 条清单**，改"一行一趟 + 问时段 + 推荐一趟"（独立文档） |
| 10 | 乘车人 | **用户自己勾**，不做自动推断、不做默认勾选 |
| 11 | 确认后的余票 | **必须重查**；卖完自动换一趟，不报错 |
| 12 | 反查性能 | 试通车改轻量存在性查询，不走完整查票 |
